## Findings considered and rejected

(Recorded so the next audit run doesn't re-litigate them.)

- **ZoneView contextmenu listener leak** (`src/views/ZoneView.ts:152`): false
  positive — `root.empty()` discards the hero element on every render; the listener
  is attached to a fresh element each time and is GC'd with it.
- **`void mountQuickCaptureSection` race** (`src/settings/tab.ts:33`): all
  `new Setting(...)` calls in that section are synchronous; the only awaits are
  inside button click handlers. No mount-ordering or teardown race exists.
- **`appendToFile` create/append race** (`src/services/capture/obsidian-vault.ts:41-50`):
  deliberate, commented race handling; worst case is line ordering in an append-only
  timestamped log. Not worth a plan.
- **Infisical CLI stderr in error toasts** (`src/services/infisical-fetch.ts:69-75`):
  the operator seeing their own CLI's stderr on their own machine is not a security
  boundary violation; `friendlyError()` already covers the common cases.
- **`buildSttProvider` loose null typing** (`src/main.ts:597`): the null case is
  handled correctly at the call site; type-hygiene only.
- **`detachLeavesOfType` in terminal `onunload`** (`src/vendor/terminal/main.ts:2101`):
  originally reported as "terminal pane wiped on every update" — WRONG: that file is
  imported by nothing (the live terminal is `src/vendor/workdesk-terminal/`). The
  violation is real but unreachable; superseded by plan 002 (delete the dead copy).
- **Terminal/PTY flow untested** (`src/vendor/workdesk-terminal/`, `pty-helper.py`):
  real gap, deliberately not planned this round — highest effort (M-L) for the
  lowest leverage (vendored-stable code). Revisit if terminal regressions appear.
- **Capture-vault error paths untested**: partially covered already —
  `tests/phase5b.spec.ts:376-396` tests createNote folder auto-creation and the
  append/create branch. Remaining gap (adapter failures) is minor.
